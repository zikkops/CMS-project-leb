# ── Scheduled jobs ───────────────────────────────────────────────────────────
# Shared secret for the scheduled loyalty reset. The scheduler sends it as
# `Authorization: Bearer <value>` on a GET to /api/admin/loyalty/reset, and the
# route compares it before doing anything. See docs/scheduled-jobs.md — the
# method has to be GET, and POST returns a 401 that reads like a wrong secret.
#
# That route zeroes every customer's points balance, so the handler FAILS
# CLOSED when this is unset — it returns 503 rather than running. An unset
# secret must never mean "anyone may call this", because unset is exactly the
# state nobody is watching for.
#
# Any long random string. Set the same value in the host's cron job.

# ── 3. Image hosting (imgbb) ────────────────────────────────────────────────
# Use a SEPARATE imgbb account from production. Sharing the key means demo
# uploads land in the live café's shared media library.
#
# Free key: imgbb.com → Get API key.
#
# ONE variable, and deliberately NOT NEXT_PUBLIC_. Every upload goes through
# /api/upload-image (or /api/import-image for the bulk wizard), which attaches
# the key server-side — the browser never sees it. A NEXT_PUBLIC_ copy used to
# be listed here as taking "the same value"; nothing read it, and anything with
# that prefix is inlined into the client bundle, so filling it in published the
# key to every visitor. That is the precise leak the proxy exists to prevent.
#
# Leave blank to start. Image upload will fail with a clear error; nothing else
# is affected.

IMGBB_API_KEY=


# ── 3b. The three hostnames ─────────────────────────────────────────────────
# Two pairs that sound alike and do different jobs. Leaving all four unset is
# a working configuration: every path is served on every host, which is what a
# single-domain deployment wants.
#
# ADMIN_HOST / POS_HOST — the SPLIT. proxy.ts reads them on the server to
# decide which hostname may serve /admin and /pos. Set ADMIN_HOST and the
# customer domain returns a bare 404 for /admin — not a redirect, not a login
# page, nothing that confirms an admin panel exists.
#
#   Deliberately NOT NEXT_PUBLIC_. A public copy would inline the admin
#   hostname into every visitor's JS bundle, which is the one thing the split
#   exists to prevent.
#
#   Bare hostname, no scheme and no path. Set each one only once its DNS
#   actually resolves — the host stops serving those paths the moment you do.

ADMIN_HOST=
POS_HOST=

# NEXT_PUBLIC_ADMIN_URL / NEXT_PUBLIC_POS_URL — the LINK. Where the customer
# site sends a staff member who is already signed in: the Navbar shortcut, the
# hero, and the post-login redirect. Unset means those simply are not
# rendered, which is the correct answer for an operator who wants the admin
# panel undiscoverable from the customer site. Staff type the URL.
#
#   Setting one is a decision to publish that hostname to every visitor, since
#   an inlined NEXT_PUBLIC_ value is in the bundle whether or not the viewer
#   is staff. That is the trade; it is not a leak, but do it on purpose.
#
#   ⚠ INLINED AT BUILD TIME. Setting these in the host's control panel after
#   deploying does nothing — they have to be present when `npm run build`
#   runs. Rebuild after changing them.
#
#   Full origin, scheme optional (https:// is assumed), trailing slash fine.

NEXT_PUBLIC_ADMIN_URL=
NEXT_PUBLIC_POS_URL=
